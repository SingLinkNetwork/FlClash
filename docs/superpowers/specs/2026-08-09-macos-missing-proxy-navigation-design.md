# macOS 配置存在時保留代理頁入口設計

## 背景

上游 [#2294](https://github.com/chen08209/FlClash/issues/2294) 回報 macOS 導入配置後，左側沒有「代理」頁，因而無法查看或選擇節點；同時儀表板的網路檢測顯示逾時。這個回報發生在 macOS 15.7.8、FlClash 0.8.94。

目前導航資料在初始化完成後，會用即時代理群組是否非空來決定「代理」頁是否存在。只要核心尚未成功載入配置、載入仍在進行，或取得代理群組失敗，即使使用者已經有配置檔，「代理」頁也會被整個隱藏。這使得使用者無法進入空狀態查看問題，也無法把「沒有節點」和「沒有配置」區分開。

## 目標

1. 使用者已有至少一個配置檔時，桌面與行動版都保留「代理」頁入口。
2. 沒有配置檔時仍可隱藏「代理」頁，避免新使用者看到沒有用途的空入口。
3. 沒有代理群組時只顯示現有空狀態，不偽造節點、不把核心或配置錯誤靜默當成成功。
4. 以自動化回歸測試固定上述行為，避免之後因核心資料暫時為空再次把入口藏掉。

## 方案

- 將導航項目的條件由「目前已有代理群組」改為「目前已有配置檔」。
- 移除初始化前後兩套不同判斷，讓入口在載入中的狀態也保持穩定。
- 保留 `ProxiesView` 目前的空狀態呈現；本輪不自行猜測上游使用者的訂閱格式，也不捏造節點資料。
- 在純導航測試中覆蓋「有配置、無群組」及「無配置」兩個邊界，並確認桌面與行動模式都能取得相同代理導航項目。

## 不在本次範圍

- 不把核心載入失敗改成自動忽略或強行啟動。
- 不更改訂閱解析、核心網路檢測或節點資料格式；若入口恢復後仍能穩定重現「有配置但無節點」，另建獨立 issue 追查其核心/訂閱根因。

## 驗收標準

- 有配置檔且代理群組為空時，`PageLabel.proxies` 仍存在於桌面與行動導航清單。
- 沒有配置檔時，代理導航項目仍不出現在清單中。
- 回歸測試、Dart 測試、分析、格式與差異檢查通過。
- 推送後，同一個提交的完整跨平台 CI/CD（Android、macOS、Windows、Linux、Dart 測試與總閘門）全部成功，才可關閉下游 issue。
