# Windows 卸載與資料清理設計

## 背景

上游 #2155 回報 Windows 版卸載後設定仍然存在，且使用者無法確認開始選單捷徑是否已建立。現有 Inno Setup 模板已建立開始選單捷徑，但應用程式在不可寫入的安裝目錄時，會把資料放在 Windows 使用者資料夾；這些安裝器未追蹤的資料不會由一般卸載自動刪除。

## 目標

1. 保持現有開始選單捷徑，並把它納入自動檢查。
2. 一般卸載時讓使用者明確選擇是否刪除 FlClash 設定與快取。
3. 預設不刪除使用者資料，避免誤刪設定；選擇清理後才刪除已知的資料位置。
4. 讓 Windows CI 實際安裝、建立測試資料、執行清理卸載並驗證資料消失。

## 已知資料位置

- `%APPDATA%\\com.follow\\clash`
- `%LOCALAPPDATA%\\com.follow\\clash`
- 可攜版或可寫入安裝目錄旁的 `{app}\\data`
- 可攜版或可寫入安裝目錄旁的 `{app}\\cache`

## 驗收標準

- 安裝器產物包含 `{autoprograms}\\FlClash` 開始選單捷徑。
- 一般卸載不清除使用者資料，除非使用者確認清理。
- 清理卸載會停止 FlClash 相關程序，並刪除上述資料位置；不存在的目錄不造成卸載失敗。
- Windows CI 能以非互動清理參數完成安裝與卸載回歸測試。
- Dart 測試、靜態檢查、五平台建置與總 CI 閘門全部通過。

## 不在本次範圍

- 不改變資料夾命名，避免造成既有使用者設定遺失或搬遷。
- 不把一般卸載改成無條件刪除資料。
