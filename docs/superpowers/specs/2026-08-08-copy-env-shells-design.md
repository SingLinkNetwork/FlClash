# #2195 複製環境變數 Shell 子選單設計

## 目標

處理上游問題 #2195：在桌面版托盤的「複製環境變數」下提供 Bash、Fish、Zsh、PowerShell 四種指令格式，讓使用者能直接貼到對應終端機使用。

## 現況與邊界

- 目前托盤只有一個環境變數複製項目。
- 目前指令格式只按 Windows/非 Windows 二分，無法選擇 Fish，也不能準確表達 PowerShell 賦值語法。
- 本次只處理桌面托盤與指令產生，不改核心代理埠、不新增網路請求、不改 Android 行為。
- Linux 現有 Wayland/X11 原生剪貼簿優先策略保留；其他桌面平台使用 Flutter 剪貼簿。

## 方案選擇

1. **推薦：純指令產生器 + 托盤子選單**
   - 以明確的 Shell 類型產生指令，指令產生器不依賴作業系統，容易測試。
   - 托盤只負責建立四個子項目與呼叫複製流程。
   - 可精確驗證每一種指令，改動集中且可回溯。
2. 只增加四個固定字串並在回調內判斷。
   - 改動初期較少，但格式邏輯與 UI 綁在一起，難以測試和維護。
3. 依目前作業系統自動猜 Shell。
   - 操作少一步，但 macOS/Linux 使用者可能使用不同 Shell，Windows 也可能使用 CMD 或 PowerShell，猜測不可靠。

本次採用方案 1，因為它同時滿足上游需求與跨平台可驗證性。

## 指令格式

以目前代理埠 `7890` 為例，使用同一個 `all_proxy` 變數名稱：

- Bash：`export all_proxy=http://127.0.0.1:7890`
- Zsh：`export all_proxy=http://127.0.0.1:7890`
- Fish：`set -gx all_proxy http://127.0.0.1:7890`
- PowerShell：`$env:all_proxy = 'http://127.0.0.1:7890'`

URL 由埠號產生，不接受外部文字輸入，因此不引入 Shell 注入風險。

## 元件與資料流

1. 純函式接收 Shell 類型與代理埠，回傳一行指令。
2. `Tray` 建立「複製環境變數」子選單，四個項目各自傳入 Shell 類型。
3. 使用既有剪貼簿流程複製結果；Linux 先嘗試原生剪貼簿工具，失敗再使用 Flutter 剪貼簿。

## 錯誤處理

- 指令產生器只接受程式內的四種列舉值，不處理任意 Shell 文字。
- 剪貼簿失敗時沿用現有回退策略，不讓托盤回調拋出未處理例外。
- 不修改代理狀態；即使複製失敗，代理仍保持原狀。

## 驗證

- 先新增四種 Shell 的失敗測試，確認實作前測試會失敗。
- 單元測試驗證四種完整指令與不同埠號。
- 靜態驗證確認四種子選單項目、回調與剪貼簿流程都存在。
- 本機跑目標測試、完整 Flutter 測試、格式檢查與分析。
- 推送後由 GitHub Actions 執行 Dart、Flutter、Go、Linux、Windows、macOS、Android 及相關靜態檢查；全部成功後才處理下一個上游問題。

## 非本次範圍

- 不新增 CMD、Bash profile 自動寫入、永久修改使用者環境變數。
- 不更改訂閱、代理核心或系統代理設定。
